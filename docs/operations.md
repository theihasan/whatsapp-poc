# Operations

## Monitoring

| Signal                                                                      | Where                                                                                                                                                |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| App, DB, Redis, provider/gateway health                                     | Dashboard → System health; `GET /up`                                                                                                                 |
| Gateway liveness / readiness (session counts, outbox backlog, dead letters) | `GET 127.0.0.1:3100/health`, `/ready`                                                                                                                |
| Queues, throughput, failed jobs, wait times                                 | `/horizon` (snapshots every 5 min)                                                                                                                   |
| Stuck work                                                                  | `app:reconcile-messaging` (every 5 min) re-dispatches pending events > 10 min and queued messages > 30 min, flags `processing` > 15 min as `unknown` |
| Gateway reconnects                                                          | gateway logs `connection closed` with `kind`; device connection history page                                                                         |
| Outbound failures                                                           | Dashboard failed/unconfirmed tile; failed-message notifications                                                                                      |
| Duplicate events                                                            | `gateway_events` unique `event_id` → webhook returns `200 duplicate`; inbound dedup on `(account, external_id)`                                      |
| Event latency                                                               | `gateway_events.created_at` vs `processed_at`                                                                                                        |
| Disk                                                                        | `deployment/scripts/disk-check.sh` (cron, optional `ALERT_WEBHOOK_URL`)                                                                              |

Logs are JSON (gateway, pino) with `reqId` = `X-Correlation-Id` sent by Laravel. QR codes, credentials, tokens, media and message text are redacted.

## Backup & restore

- **Nightly** `deployment/scripts/backup.sh`: `mysqldump --single-transaction` + private attachments, encrypted with `age` to an offline recipient key, 14-day local retention. Ship the `.age` files off-host.
- **Gateway state** is included only with `BACKUP_GATEWAY_STATE=1` (online `sqlite3 .backup`). It is useless without `GATEWAY_STATE_KEY`, which must be stored separately (password manager/KMS). If you do not back it up, devices simply need re-linking after a disaster.
- **Restore test (do quarterly):** decrypt (`age -d -i key.txt backup.tar.gz.age | tar -xz`), `mysql whatsapp_workspace < database.sql` into a scratch DB, untar attachments, start the app against it, open a conversation with an attachment. For gateway state: stop the gateway, place `gateway.sqlite` in `GATEWAY_DATA_DIR`, start with the same `GATEWAY_STATE_KEY` → sessions restore without QR.

## Troubleshooting

Category: **App** = application error · **Infra** = infrastructure/configuration · **Provider** = WhatsApp/Meta limitation · **Protocol** = Baileys/WhatsApp Web uncertainty.

| Symptom                              | Likely cause                                                                                                                              | Check / fix                                                                                                                                                                               | Category         |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| QR does not appear                   | Gateway unreachable or wrong token; Horizon not running (events not processed)                                                            | Device shows _Failed: gateway unreachable/rejected_ → check `GATEWAY_URL`, tokens, `/ready`. Gateway events stuck `pending` → start Horizon.                                              | Infra            |
| QR expires before scanning           | Codes rotate ~every 20 s; Baileys gives up after several                                                                                  | Scan promptly; press _Generate new code_ (re-pairs). Mock: codes last `MESSAGING_QR_TTL`.                                                                                                 | Protocol         |
| Device keeps disconnecting           | Unstable network, phone offline for long, WhatsApp closed the socket                                                                      | Connection history reasons; gateway retries with backoff up to `GATEWAY_MAX_RECONNECT_ATTEMPTS`, then _Failed_ → Reconnect.                                                               | Protocol / Infra |
| _Logged out_ unexpectedly            | Device removed on the phone, or WhatsApp invalidated the session                                                                          | Re-link (new QR). Credentials were deleted by design.                                                                                                                                     | Provider         |
| _Failed: refused (403)_              | Number restricted by WhatsApp                                                                                                             | Use another test number; do not retry aggressively.                                                                                                                                       | Provider         |
| Session cannot restore after restart | `GATEWAY_STATE_KEY` changed, data dir moved/permissions                                                                                   | Gateway logs decrypt errors → restore the original key or re-link. Check `GATEWAY_DATA_DIR` ownership/0700.                                                                               | Infra            |
| Message _Failed_                     | Rejected (invalid recipient, unsupported media) or retries exhausted while session disconnected                                           | Read the reason on the bubble; fix and _Retry_.                                                                                                                                           | App / Provider   |
| Message _Not confirmed_              | Timeout after handing to the gateway; worker killed mid-send                                                                              | Check the phone/recipient first; _Retry_ reuses the idempotency key, so the gateway returns the original message if it went out.                                                          | Protocol         |
| Webhook not received                 | Wrong `GATEWAY_WEBHOOK_URL`, clock skew > 300 s, secret mismatch (401), app down                                                          | Gateway `/ready` outbox pending/dead counts and logs `webhook delivery failed`/`dead-lettered`; `timedatectl` (NTP); compare secrets. Dead letters need manual re-send (re-enqueue rows). | Infra            |
| Message appears twice                | Should not happen (event + external id dedup). If it does: two devices linked to the same number, or a message sent from the phone itself | Compare `external_id`s; file a bug with both rows.                                                                                                                                        | App              |
| Browser gets no live updates         | Reverb down; wrong `VITE_REVERB_*` baked into assets; nginx `/app` proxy missing; CSP `connect-src` mismatch                              | Inbox shows the offline banner; browser console; `SECURITY_WS_ORIGIN`; rebuild assets after changing `VITE_*`.                                                                            | Infra            |
| Horizon not processing               | Horizon stopped, Redis down, or code deployed without `horizon:terminate`                                                                 | `supervisorctl status`, `/horizon`, Redis `PING`.                                                                                                                                         | Infra            |
| Gateway crashes after restart        | Invalid env (process exits listing variables), Node < 22.18, corrupted SQLite                                                             | Run `npm start` manually to see the config error; `node -v`; restore `gateway.sqlite` from backup or remove it and re-link.                                                               | Infra            |
| Automation didn't fire               | Rule disabled/dry-run, rate limit, auto-reply disabled in settings, provider capability                                                   | Automations → Execution log shows the exact skip reason.                                                                                                                                  | App              |
