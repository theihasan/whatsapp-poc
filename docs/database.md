# Database

MySQL is the source of truth for business data (tests use in-memory SQLite, D-010). Protocol credentials never live here — they are in the gateway's encrypted SQLite file (D-007).

## Entities

| ------------------------------------------------------ | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `whatsapp_accounts`                                    | ULID           | Linked device. `provider`, `status` (state machine), `phone_number`, `wa_jid`, `last_error`. **Its id is the gateway session id.**                        | status                                                                                                                                                                                    |

| `messages`                                             | ULID           | `direction`, `type`, `body`, `external_id`, `idempotency_key`, `status`, `failure_reason`, `is_automated`, `sent_at`/`delivered_at`/`read_at`, `metadata` | unique (account, external_id) — inbound dedup; unique idempotency_key — outbound dedup; (conversation, id) — cursor pagination; (direction, created_at), (status, created_at) — dashboard |

ULIDs are used for every id that appears in URLs or broadcasts; they sort chronologically, which the message cursor (`id < before`) relies on.

Not created (see `docs/decisions.md`): `workspaces`/`workspace_user` (single workspace, D-002), `conversation_assignments` (audit log instead, D-009), `outbound_message_requests` (idempotency key on `messages`, D-008), `campaigns`/`campaign_recipients` (deferred, D-003).

## Write paths

All multi-row writes run in transactions: inbound message (contact + conversation + message + counters), outbound queueing (message + attachment + conversation), status updates (row lock on the message), device transitions (row lock on the account + history row). Broadcast events are dispatched after commit.

## Retention (`app:prune-records`, daily 03:15)

| Data                               | Kept                     | Setting                                |
| ---------------------------------- | ------------------------ | -------------------------------------- |
| processed/ignored `gateway_events` | 30 days (failed kept)    | `RETENTION_GATEWAY_EVENTS_DAYS`        |
| `automation_executions`            | 90 days                  | `RETENTION_AUTOMATION_EXECUTIONS_DAYS` |
| `device_connection_events`         | 180 days                 | `RETENTION_DEVICE_EVENTS_DAYS`         |
| `audit_logs`                       | 365 days                 | `RETENTION_AUDIT_LOGS_DAYS`            |
| read notifications                 | 30 days                  | `RETENTION_READ_NOTIFICATIONS_DAYS`    |
| failed jobs                        | 14 days                  | scheduler                              |
| messages, contacts, consents       | not pruned automatically | —                                      |
| gateway temp media / send ledger   | 24 h / 30 days           | gateway housekeeping                   |

Seed data (`php artisan db:seed`) uses only the NANP fictional range 555-01xx and mock devices.
